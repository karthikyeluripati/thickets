# Bounded real-LLM pilot: October 3, 2026

Candidate-state manipulation is a small latency component in the tested
Qwen2.5-0.5B HF eager generation workloads. Eliminating apply and restore entirely
would give at most a **1.023x** speedup over the exact snapshot baseline here.
This supports deferring a latency-focused state kernel for these workloads.
Optimized inference engines, other evaluation regimes, larger models, and
memory-constrained execution remain open questions.

Legacy add/subtract fails exact restoration in every run. At 128 tokens and batch
4, three of four sequential candidates also produce different generated outputs
**and different scores** from independently snapshot-anchored versions of the same
recipes. Snapshot-copy passes all measured gates. Correctness is a concrete runtime
concern even when state latency is small.

- One NVIDIA H100 80GB HBM3; driver 580.126.09. GPU idle before and after this work.
- Python 3.12.3, PyTorch 2.8.0+cu128, CUDA runtime 12.8, Transformers 4.56.2.
- Model: `Qwen/Qwen2.5-0.5B`, revision
  `060db6499f32faf8b98477b0a26969ef7d8b9987`, non-quantized BF16.
- Runtime source: `c5cc037e66ef30b2d474c4d5135b7a3023615178`, unchanged.
  Source hashes are preserved. Later manifests may list the newly added
  analysis/reproduction scripts as untracked.
- HF eager attention, greedy decoding, fresh KV state per call, one host thread,
  original per-tensor RNG and cache-cleanup policy.
- Seeds 42–45, sigma 0.001, four candidates, two warmups per strategy, three
  repeated traces: 12 timed evaluations per strategy per case. Audits, loading,
  hashing, snapshot creation, and warmups are outside the reported timings.
- Fixed 32/128 new-token budgets. Batch 4 uses all four arithmetic smoke prompts;
  batch 1 uses the first. These are execution-cost microbenchmarks with real
  weights, **not representative task-quality data**.
- Fixed strategy order: legacy, then snapshot. These are single-process repeated
  traces, not independent experimental replicates.

The earlier failed model-loading attempt remains intact on the pod. Its cause was
an enabled but uninstalled `hf_transfer` accelerator. This session disabled the
optional accelerator and used a new output directory. No numerical runtime code
was changed to obtain these results.

## Timings

Times below are arithmetic means of synchronized wall spans. State fraction is
`sum(apply + restore) / sum(total)`; the bound is `1 / (1 - state_fraction)` with
all other work held fixed. CUDA event intervals are not added to wall time.

| New tokens | Batch | Strategy | Apply ms | Inference ms | Restore ms | Total ms | State fraction | Ideal bound |
|---|---|---|---:|---:|---:|---:|---:|---:|
| 32 | 1 | Legacy | 8.18 | 515.46 | 8.25 | 532.16 | 3.088% | 1.0319x |
| 32 | 1 | Snapshot | 9.82 | 522.20 | 2.13 | 534.39 | 2.237% | 1.0229x |
| 32 | 4 | Legacy | 8.56 | 572.44 | 8.95 | 590.37 | 2.967% | 1.0306x |
| 32 | 4 | Snapshot | 9.98 | 556.08 | 2.05 | 568.47 | 2.117% | 1.0216x |
| 128 | 1 | Legacy | 7.75 | 2029.64 | 8.23 | 2046.00 | 0.781% | 1.0079x |
| 128 | 1 | Snapshot | 9.42 | 2029.56 | 2.29 | 2041.60 | 0.573% | 1.0058x |
| 128 | 4 | Legacy | 8.12 | 2069.30 | 8.79 | 2087.01 | 0.810% | 1.0082x |
| 128 | 4 | Snapshot | 9.91 | 2065.23 | 2.38 | 2078.11 | 0.592% | 1.0060x |

Scoring means range from 0.15 to 0.70 ms. Totals include scoring and harness gaps,
so the displayed phases do not sum to total time. Inference accounts for roughly
96.8–99.4% of wall time. State cost stays roughly constant as token budget grows.

The separate 32-token, batch-4 wall-only control gives:

| Strategy | Total ms | State fraction | Ideal bound |
|---|---:|---:|---:|
| Legacy | 552.67 | 2.872% | 1.0296x |
| Snapshot | 550.51 | 2.125% | 1.0217x |

The state-fraction conclusion survives this control. Total times differ by
about 3.2–6.4% from the event-enabled invocation, larger than many between-strategy
differences. Separate-process variation, fixed strategy order, and instrumentation
are confounded; this is not an isolated estimate of CUDA-event overhead or evidence
of a reliable end-to-end strategy speedup. The synthetic pilot's roughly 1.43x
throughput ratio does not transfer to these LLM workloads.

The analysis preserves all three repeat means as descriptive variation, not
independent-run confidence intervals. For example, 32-token batch-4 legacy repeat
means span 578.64–609.77 ms, while snapshot spans 567.31–569.90 ms. Counterbalanced
independent invocations remain necessary for a small performance claim.

## Correctness and memory

Each audit compares four sequential candidates with independent snapshot-anchored
candidates. Output equality means generated token-tensor agreement, not hidden-logit
bitwise equality.

| Tokens / batch | Legacy output matches | Legacy score matches | Snapshot output / score matches |
|---|---:|---:|---:|
| 32 / 1 | 4/4 | 4/4 | 4/4 and 4/4 |
| 32 / 4 | 1/4 | 4/4 | 4/4 and 4/4 |
| 128 / 1 | 3/4 | 4/4 | 4/4 and 4/4 |
| 128 / 4 | 1/4 | 1/4 | 4/4 and 4/4 |

The wall-only control repeats the 32/4 pattern. All five legacy exact-semantics
gates fail, including when outputs and scores happen to agree. After each
four-candidate legacy trace, **20.063%** of parameter values differ from the base;
maximum absolute drift is **0.00390625**. Snapshot has zero measured parameter/buffer
drift and passes all five output, reward, and reset gates. The small arithmetic
scorer does not establish an accuracy degradation rate on a research benchmark.

Both paths retain a **0.92021 GiB** logical parameter snapshot and peak near
**2.39486 GiB** CUDA allocated memory. Snapshot-copy does not eliminate the base
snapshot. These are allocator measurements, not HBM traffic or whole-process
resident memory. No capacity pressure was demonstrated on the 80 GB H100.

## Research decision

Keep snapshot anchoring as the correctness reference. A state-only latency change
has less than 2.3% ideal speedup headroom over this reference in the tested
32-token workloads and less than 0.6% in the 128-token workloads. These results do
not justify an ephemeral/streamed perturbation kernel for this HF eager workload yet.

Next, measure the same lifecycle under the intended optimized inference backend
and a representative frozen scoring set. Include short evaluations or
prefill/log-likelihood scoring if those are actual target workloads. Preserve
candidate identity and cache isolation. HF eager results are not vLLM/Ray or
original-RandOpt throughput. Counterbalance strategy order and repeat whole
processes before interpreting percent-level gains.

The memory-capacity hypothesis remains open: avoiding a model-sized snapshot could
permit otherwise infeasible workloads. Measure that constraint at the target model
size first. Stateless/streamed designs must retain explicit RNG/numerical contracts
and account for repeated noise generation across decode steps. Shard-local
generation requires a separately validated contract; this pilot says nothing about
tensor parallelism.

The runner refuses an existing destination, executes five cases serially, and
bounds each process to 900 seconds including loading and audits. This session's
first case had a 900-second limit; subsequent cases had 600-second limits. The
runner codifies the executed commands with a uniform limit. Its shell syntax and
Python code were checked; the full runner was not rerun after packaging. The
summarizer was executed on all five completed reports. The GPU suite passed
**43 tests, with one CPU-only guard skipped**. No optimized kernel was implemented,
and no GPU job remains running from this session.

All ten derived strategy summaries were checked against the original summaries;
all 120 timed rows were validated for trace identity and repetition count. The
five runs share the same candidate identities. Git whitespace checks passed.
